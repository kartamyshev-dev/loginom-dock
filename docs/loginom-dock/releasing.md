# Подготовка выпуска Loginom Dock

Клиентский кандидат: `0.1.0-rc.1`. Сборки выполняются на сервере Dock для
`darwin-arm64` и `linux-x64`. Публикация выполняется в GitHub Releases проекта
`kartamyshev-dev/loginom-dock`; до неё ссылки загрузки в Studio остаются пустыми.

## Состав

Каждый архив содержит Node.js 24.19.0, закреплённые зависимости браузера/MCP,
оба native-плагина, мастер `install.sh`, `client/INSTALL.md`, лицензии и
`release.json`. В manifest входят версия, исходный commit, признак чистоты
исходников, совместимость с агентами и контрольные суммы файлов.

Версия клиента, двух plugin manifests и ревизии hooks должны совпадать.
Чистый commit — обязательное условие публичной pinned-установки Hermes:
флаг `--source-clean` разрешён только для снимка, совпадающего с этим commit.
Локальные `.env`, `.dock`, персональные настройки и ключи не включаются.

## Проверки перед публикацией

1. Зафиксировать исходники и проверить чистоту Git. Создать клиентский снимок
   через `deploy/loginom-dock/package-client-source.py`; сверить его содержимое
   с деревом указанного commit и SHA-256 после передачи на сервер.
2. На сервере собрать оба архива через `build-client-bundle.py`, используя
   закреплённые Node и зависимости. Проверить manifest и комплект клиентских
   тестов на Linux и macOS. Собирать на Mac повторно не требуется.
3. Сверить native-приёмку Codex и Hermes с фактическими отчётами, скриншотами
   и архивом. Hermes создаёт сценарий через уже подключённую подписку ChatGPT;
   серверные функции Dock используют модели своего активного конфига.
4. Подготовить `SHA256SUMS`, инструкцию установки и описание с проверенными
   результатами и открытыми ограничениями.
5. Проверить GitHub-авторизацию, отправить исходный commit, создать prerelease
   `v0.1.0-rc.1` на этом commit и приложить оба архива, суммы и инструкцию.
   Скачать опубликованные файлы и сверить суммы. Это проверка доставки файлов,
   а не отложенная чистая установка.
6. Только после подтверждённой публикации указать версию и реальный URL выпуска
   в `web-studio/src/lib/dock-release.ts`, собрать Studio на сервере и проверить
   страницу подключения. Записать фактические хеши и результаты в журнал.

## Отложенные проверки

По решению пользователя от 3 сентября 2026 года сейчас не выполняются проверка
чистой установки из опубликованного релиза на macOS/Linux (включая обновление,
откат и удаление) и автоматическая отправка резервных копий во внешнее хранилище.
Эти ограничения указываются в описании выпуска. Они не отмечаются выполненными.

Изменения CI в этом выпуске не требуются. При будущих изменениях CI действуют
правила синхронизации канонической документации и согласованных копий OpenViking
из `AGENTS.md`.
