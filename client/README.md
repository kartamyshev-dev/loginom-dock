# Локальный клиент Loginom Dock

Разрабатываемый общий MCP-компонент для macOS/Linux. Он обслуживает initialization,
подключает удалённый Dock и локальный Playwright MCP, объединяет их настоящие
каталоги tools, отвергает коллизии и сохраняет каталог/версии на сессию.
Для каждого запуска создаётся отдельный профиль браузера в каталоге Dock.
`dock_prepare` загружает и проверяет полный серверный skill, возвращает инструкции
в текущий контекст и закрепляет ревизию за сессией. Native-адаптеры и архив подключены к Codex и Hermes. Полная приёмка первого
релиза отражается в журнале реализации.

Зависимости фиксируются `package-lock.json`: MCP SDK 1.30.0, Playwright MCP 0.0.80.
Последний использует Playwright `1.63.0-alpha-2026-08-31` и Chromium revision 1243
(153.0.8010.12). Это комплект прототипа, его пригодность проверяется на живом Loginom.
Node.js закреплён в `.node-version` (24.19.0). Системный Node не заменяется.

Используйте закреплённый Node и `npm ci --ignore-scripts`, затем:

```sh
node bin/install-browser.mjs --state-dir /absolute/dock-state
node bin/loginom-dock.mjs --config /absolute/dock-client.json \
  --state-dir /absolute/dock-state --agent codex --adapter-revision prototype-1
```

`client.json` — обычный клиентский ключ сервера с полями `endpoint`, `api_key`,
`account` и `user` (оба `loginom-dock`), права 0600. Путь передаётся явно или через
`LOGINOM_DOCK_CONFIG`; личные `OPENVIKING_*`, `ovcli.conf` и memory provider не читаются.
Endpoint — HTTPS `/mcp`. Если `--state-dir` отсутствует, используется собственный
`~/.loginom-dock`. Для Hermes укажите `--agent hermes` и ревизию его адаптера.

Браузер видимый по умолчанию. `--headless` предназначен для технических проверок;
он не заменяет приёмку видимого Loginom. Закрытие клиентской среды закрывает её
дочерний browser MCP. Профиль и артефакты остаются локально. Сам MCP без native hooks
не активирует архив; фактический статус активации виден в диагностике.
`dock_diagnostics` показывает версии, пути и число инструментов без credentials.

`dock_clipboard_transfer` выполняет copy → paste → проверку DOM одним вызовом.
Все сессии Dock на машине используют общую блокировку: эксклюзивно занятый
loopback-порт 46419 без протокола передачи данных. ОС освобождает его при завершении
процесса; живого владельца нельзя вытеснить по таймеру. Ожидание блокировки можно
отменить. После начала copy блокировка удерживается до финального результата
браузера; при потере ответа остаётся до закрытия клиентской среды. Смена браузерных
действий внутри одной сессии также сериализована. Остальные программы не участвуют
в этой блокировке. Прямые copy/paste вне этого инструмента применять нельзя.

Конфигурационный helper `normalizeConfigPath` переиспользован из общей библиотеки
upstream-примеров. Их credential fallback и автоматический memory capture не используются.
Дистрибутив включает эти общие модули вместе с закреплёнными зависимостями.

Native hooks используют собственную SQLite-очередь в `archive/`, читают только
активированную историю Codex/Hermes и очищают события до записи и перед отправкой.
После завершения хода очередь запрашивает штатный commit OpenViking; сервер
выполняет извлечение events/experiences без смешанного персонального профиля.
Доставка повторяется ограниченным фоновым worker и при следующих hooks. Пропавшие
незаписанные streaming fragments не объявляются восстановленными.

`deploy/loginom-dock/build-client-bundle.py` собирает самостоятельный пакет с Node,
лицензиями, зависимостями, native-плагинами и SHA-256 каждого файла. `install.sh`
запускает мастер; ключ вводится скрыто либо читается из явного файла 0600 через
`--config-from`. `--runtime-only` предназначен для приёмки среды до native-установки.
Версии размещаются в `releases/`; `current` переключается атомарно, `--rollback`
возвращает предыдущую среду в режиме `--runtime-only`. Для штатной установки
`--agent codex --rollback` или `--agent hermes --rollback` восстанавливает также
native-регистрацию выбранного профиля. Мастер сохраняет журнал перед переключением;
после аварийного прерывания та же команда повторяет восстановление. Текущие ключи
при обычном откате сохраняются; при отмене неудачной установки возвращаются её
прежние настройки. При повторной установке того же комплекта цель отката не теряется.

`--agent codex --uninstall` или `--agent hermes --uninstall` удаляет подключение
и native-плагин выбранного агента. Профили, артефакты и очередь остаются в Dock-owned
каталоге. Их удаление — отдельное решение пользователя; серверная история не меняется.
Для native-установки используется `~/.loginom-dock`; нестандартный `--home` предназначен
для изолированных runtime-only проверок. Профиль Hermes задаётся `--hermes-home`.

Обновление Hermes выполняется повторной pinned/subdirectory установкой с `--ref`
полного SHA через его штатный менеджер, с сохранением сканирования плагинов.
MCP-запись меняется штатным `hermes config set mcp_servers.loginom-dock`; результат
читается обратно. Не относящиеся к Dock подключения и memory provider сохраняются.
При работающем gateway после изменения native-пакета его нужно перезапустить.

Диагностика показывает серверную identity, три источника, проверенную ревизию skill,
доступность Loginom, число ожидающих событий этой сессии и всей установки,
возраст самого старого неотправленного события. Отсутствующее время обозначается
как неизвестное. HTTP-доступность страницы не означает успешную авторизацию.
Пакеты с `sourceDirty=true` являются кандидатами и не подходят для закреплённой
публичной установки Hermes. Полная приёмка установки ещё продолжается.

Проверки: `npm test`; сквозная проверка подключает SDK-клиент к этому stdio-серверу,
читает настоящий каталог и вызывает поиск/чтение Dock и инструменты браузера.
